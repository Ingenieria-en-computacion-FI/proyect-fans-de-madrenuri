Para resolver este problema se realizaron múltiples reuniones mediante Zoom y videollamadas, algunas de ellas con apoyo de un compañero que ya había cursado la materia anteriormente.

 Distribución de tareas Con el objetivo de avanzar de forma más eficiente, el proyecto fue dividido en tres áreas principales: Mapa ● Diseño del laberinto. ● Carga de información desde archivos. ● Definición de límites y posicionamiento de elementos. Movimiento y sprites ● Implementación del movimiento del jugador. ● Integración de sprites. ● Renderizado y aspectos visuales. Sistema de juego ● Colisiones. ● Sistema de puntuación. ● Lógica general del juego y control de eventos. Además de sus responsabilidades específicas, todos los integrantes participaron en las pruebas, revisión de errores y elaboración de la documentación. 
 
 Problemas encontrados durante el desarrollo ● Dificultades de comunicación debido a incompatibilidad de horarios. ● Necesidad de coordinar múltiples reuniones mediante Zoom y videollamadas. ● Dos integrantes desarrollaban el proyecto simultáneamente a la presentación de exámenes finales de otras materias. ● Desconocimiento inicial sobre el funcionamiento del sistema RGB. ● Dificultad para comprender el posicionamiento de elementos y los límites del mapa. ● Integración de módulos desarrollados por diferentes integrantes. ● Errores de escritura y errores lógicos detectados durante las pruebas. ● Dependencia de sesiones de asesoría con un compañero que ya había cursado la asignatura para resolver dudas técnicas relacionadas con el mapa y SDL2. Decisiones de diseño ● Mantener una estructura modular para facilitar el desarrollo colaborativo. ● Utilizar archivos independientes para separar las distintas funcionalidades. ● Implementar un mapa basado en arreglos bidimensionales para simplificar la representación del escenario. ● Priorizar la funcionalidad básica del juego antes de realizar ajustes visuales.
